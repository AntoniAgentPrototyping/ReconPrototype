# sample exports

Synthetic platform exports for the `2026-05_demo` window — **no client data**, no PII.
Generated by `service/sampledata.py` (`SEED = 20260817`, deterministic), two synthetic
stores (`Demo Alpha`, `Demo Đông Á`) across all three platforms.

Regenerate with:

```bash
PY="$LOCALAPPDATA/recon-venv/Scripts/python.exe"
"$PY" -m service.sampledata --out "sample exports/xlsx"
```

## Layout

| Tree | What it is |
|---|---|
| `xlsx/2026-05_demo/...` | The generator's own output — the **canonical** form, in the real per-platform folder shape and the uniform `service/naming.py` filename scheme. |
| `csv/2026-05_demo/...` | A cell-for-cell mirror of the same workbooks, one CSV per **sheet**, UTF-8 with BOM (the encoding `src/ingest.py:211` reads CSV parts with). |

The two trees are kept apart on purpose: `ingest.read_parts` globs a folder for every
file whose suffix is in `file_formats` (`.xlsx` **and** `.csv`), so putting both
alongside each other in one folder would read every row twice.

## What the shapes preserve

These aren't cosmetic — each is a measured property of a real export, and the CSV
mirror keeps all of them:

- **TikTok orders** carry a junk row directly under the header (`skip_rows_after_header.tiktok.orders: 1` drops it). 131 rows = header + junk + data.
- **Shopee income** has two blank band rows above the leaf header (`header_rows.shopee.income: 3`) and is split across two sheets matching `/Doanh thu/`, which `read_parts` concatenates — hence `... - Doanh thu.csv` and `... - Doanh thu - 1.csv`.
- **Shopee orders for store 001** carry NFD-decomposed headers (9 of 9 non-NFC), because real exports do; store 002's are NFC. That is the case `ingest.read_parts` normalises.
- **Store identity comes from the filename**, never a column.

## Caveat on the CSV tree

`store_from_filename` patterns in `config/settings.yaml:167+` are anchored to `\.xlsx$`,
so the CSVs will **not** resolve a store if fed to the pipeline as-is. They are for
inspection, diffing and sharing the shape — run the pipeline against the `xlsx/` tree.

## Running it

The demo roster is synthetic, so a run needs the demo's pinned config version (seeded
by an admin via `POST /demo/seed`) or it trips the store-count hard stop. For a
developer run, stage `xlsx/2026-05_demo/` under `input/` and point `tools/devrun.py`
at it.
